Further findings from the recheck:

- `AlgorithmObservation<...>`, the record an algorithm observation carries, lives in `Algorithms/BaseClasses` in namespace `Algorithms` and derives from `Observation<TProblem>`. Moving `Observation` into Analysis would create a new Algorithms-to-Analysis edge.
- The two run kinds share less lifecycle than the report implies. `AlgorithmRun` pauses and resumes, and cancels from `Running` or `Paused`. `ExperimentRun` never pauses, treats cancellation as terminal, ends in `Stopped` when its stream is disposed early, and refuses to start once a trial was started directly. What they share is the lock, the state, the preparation guard, the start transition and the guarded transition out of `Running`.
- `LexicographicComparer` does not check its order's length against the objective count today. A shorter permutation silently skips dimensions, and a longer one fails inside `Compare`.
- Contracts internals are currently protected by the assembly boundary: the `ResolutionScope` and `ResolutionScopeBuilder` constructors, `ResolutionScopeBuilder.Build`, `Decoration`, and `AlgorithmRun.StreamForTerminalCancellation` and `CancelAsync`. After consolidation every main-project file can reach them.

`HeuristicLib.Contracts` now has 39 C# files and about 92 public type declarations. It contains concrete code including `ResolutionScope`, `ValueArray`, objective values, experiment setup and two run hosts. In this repository the main project is its only direct source-project consumer; Experimental and PythonInterop reference the main project. No Contracts file has a same-path collision in the main project. CI packs Contracts as a separate NuGet package and pushes it to nuget.org. The accepted direction is to fold it into the main project. This removes a lightweight package with no external dependencies and changes assembly identity for its public types, while preserving C# namespaces and source call sites where the namespace split does not change them. The layer rules will govern concepts within the main assembly.

## Settled branch decisions

These choices fix the destinations for public files, so no file has to move twice.

| Decision | Direction |
| --- | --- |
| Host namespace | Keep `AlgorithmRun`, `ExecutionStream`, `RunLifecycleState` and the planned internal host in `HEAL.HeuristicLib.Execution`, with their source files grouped under `src/HeuristicLib/Execution/Runs`. Keep `ExperimentRun` in `Experiments`. This avoids another public namespace; hosting ownership is enforced by type and source location, even though hosting and resolution share `Execution`. |
| Analyzer type | Keep `IAnalyzer : IExecutionModule`, with no `Install` redeclaration, for analyzer authoring and `IRankAnalyzer`. The run and experiment host use `IExecutionModule` in signatures and storage. Do not introduce an `Analyzer` base solely to replace this interface. |
| Trial factories | The experiment host owns `TrialModule<TAlgorithm, TModule>` and `TrialAttachment<TTrial, TModule>`. Users call `AlgorithmRun.Attach`, `ExperimentRun.AttachPerTrial` and `GetAttached`; the neutral method names work for analyzers and other modules. `GetAttached` returns trial/module pairs with `Trial` and `Module` properties. Analysis keeps only `TrialAnalyzer.Create` as a convenience over `TrialModule.Create`; separate analyzer attachment and lookup methods are unnecessary. These methods serve the attachment mechanism retained by the DI/AOP plan, whose later terminology work may revisit type names. |
| Sink names | Rename `ObservationCounter` to `CountAccumulator` and `ObservationDuration` to `DurationAccumulator`, under `HEAL.HeuristicLib.Instrumentation`. Preserve their current members and atomic behavior. Experimental's legacy `EvaluationsCounter` is narrower and does not replace either sink. The per-role counting and duration wrappers stay with their roles in `Operators.*`; the doctrine says so, because a reader will look for them under `Instrumentation`. |
| Dynamic-problem analysis | Move the three files in `Problems/Dynamic/Analysis`, `EpochClock`, `EpochWork` and `BestBeforeChangePerformanceAnalyzer`, into namespace `HEAL.HeuristicLib.Analysis`, following Experimental's other analysis. The abstract `Clock` types then stay in Analysis; no `Clocks` namespace is introduced. |
| Observation hook | `Observation` stays in `Execution`, and the `Observe` mechanism stays in Analysis. `IterationUpdateModule` stays in `DynamicProblem.cs`. `Problems.Dynamic → Analysis` for `Observe` is the one named exception in the doctrine; the AOP branch removes it when advice replaces the observation hook. Moving these now would move files that branch reworks. |
| Assembly split | Move all Contracts source into `HeuristicLib`, then remove the Contracts project and NuGet package. Keep the public concept namespaces except for the changes listed here. |

Other placements follow from those choices. Keep `ExecutionSignature`, configuration contracts, modules, resolution and `Observation` in `Execution`. Keep `ExecutionConcurrency`, `ExecutionConcurrencyKind` and `BatchExecution` in the `Execution` namespace, with their source files grouped under `src/HeuristicLib/Execution/Concurrency`. These shared helpers belong to library content and can be used by operators, problems, encodings and experiments without depending on hosting. A separate namespace would add imports without a demonstrated need; classify these helpers by type alongside the composition and resolution types that also use `Execution`. Put `SearchConfigurationValidation` in `Execution`, beside `ExecutionSignature`. Its `SearchSpaceCompatibility` dependency is another composition check over contracts, not a concrete library-content dependency; keep that check in `SearchSpaces` to avoid moving an otherwise unchanged public API.

## Target rule

Document a stack of domain vocabulary, composition model, resolution, library content, hosting, and analysis. A higher layer may depend on a lower one. The creation members of configuration and role authoring contracts name `ResolutionScope` as a parameter; this narrow L1-to-L2 signature bridge is intentional and does not transfer resolution ownership to those contracts. Configuration and execution instances are phases within those responsibilities: configurations describe reusable graphs, resolution creates run-bound instances, and instances execute. They are not successive layers.

The checks that matter most here are: hosting does not reference Analysis or concrete library algorithms; operators, algorithms and problems do not reference Analysis; Objectives does not reference concrete encodings; and the main assembly does not reference Experimental. Analysis conveniences may attach to runs, since that dependency points downward. State the exceptions explicitly in the doctrine rather than hiding them in a namespace test; this branch ends with exactly one, the dynamic problem's use of `Observe`.

The doctrine assigns layers through a table of namespaces and, where a namespace mixes layers, of type kinds. `Algorithms`, `Operators` and `Problems` hold both composition-model contracts, such as `IAlgorithm`, `IMutator` and the role bases, and concrete library content, so "hosting does not reference concrete algorithms" is a type-level rule: interfaces and authoring bases belong to the composition model, instantiable configurations to library content. The table also places `Instrumentation`, the concurrency and hosting types in `Execution`, `Experiments`, Experimental and PythonInterop, which sits above everything as integration. The architecture test follows the same table.

Resolution and run internals are reachable only from the layer that owns them: internal members of `ResolutionScope`, `ResolutionScopeBuilder` and `Decoration` from resolution code under the `Execution` source folder, excluding its `Runs` and `Concurrency` grouping folders, and the run's internal stream and cancellation entry points from hosting code under the `Execution/Runs` and `Experiments` source folders. Sharing the `Execution` namespace does not grant hosting code access to resolution internals. Consolidation removes the assembly boundary that enforced this, so the architecture test enforces it instead.

## Definition of done

- The doctrine and guideline state an enforceable downward dependency rule, assign namespaces and mixed-namespace type kinds to layers, and explain why configuration and execution are phases. The architecture test checks the forbidden edges and the internals rule, and its allowlist contains only the dynamic problem's use of `Observe`.
- No operator, algorithm or host source depends on Analysis, and no problem source does beyond the named exception. No objective source depends on a concrete encoding. The old analyzer-to-run conceptual cycle is gone: the run accepts and installs modules only, through one list. `DeclareAsModule` is removed.
- The chosen public names and namespaces have one home each. Contracts no longer builds or packs, and its former source files appear as moves in the main project. The intended behavior changes are installation by attachment order across analyzers and modules, and `LexicographicComparer` rejecting an order of the wrong length. Configuration-origin precedence and direct analyzer decoration still behave as before.
- `AlgorithmRun` holds a façade over immutable composition, its scope and a `RunHost`. `ExperimentRun` uses the host's lifecycle transitions. `RunHost` has unit tests of its own. Public fluent behavior, trial result lookup, streaming, cancellation and pause semantics have focused coverage.
- Focused tests run during each change. Run the full `HeuristicLib.Tests` project after meaningful core changes, then API usage specs and Experimental tests for the public moves. Run Scenarios once near the end. Because this is a cross-project public API change, run the complete solution tests for final validation.
- Run `dotnet restore`, `dotnet build --configuration Release --no-restore`, the selected release tests, and all three `dotnet format ... --verify-no-changes --no-restore` commands from `AGENTS.md`. Run `npm run docs:build` and fix broken documentation links or snippets it detects. Record any pre-existing formatting failures separately; a green CI formatting job is not proof of cleanliness.
- Leave the git index and commits entirely to the reviewer.
